# 手机使用和再次办理的时点选择

**目标**　让模拟人物先决定无待办时要不要用手机，遇到挫折后自己决定何时再看这件事。第 4–7 天的设备活动只用于事后比较。

## 正常运行

- [x] 在 `config_runtime.py` 和 `run_social_memory_week.py` 为机会模式选择新提示版本。按归档版本运行的既有实验保持可复核。
- [x] 在 `proto/app_entry/needs.py`、`planner.py`、`rollout.py` 和 `intention_contract.py` 中，根据实际可办理的机会确定是否先询问使用意愿。无事可办时，需求模型明确选择用或不用；选择使用后，计划模型再给出实际打开的频道。预约尚未到点时也使用这条路径。
- [x] 在 `proto/retry_review.py`、`hourly_intention.py` 和 `agent.py` 中，让模型在读到刚结束的回避、失败或中途放弃经历后选择合法的复查日和钟点。成功直接结算。模型回复无效时保留原结果，单列缺测。

## 验证

- [x] 在验收器中核对真实发送的观察、模型回复、执行结果及下一次可办理的时点。用显式选择不用、使用、跨日预约、坏回复以及存在可办理任务的场景做离线回归。
- [x] 运行 `examples/digital_friction_mvp/tests`，再用上一轮已冻结的十人七天数据重做验收。
- [x] 用上一轮的凌晨和白天时点做小样本复问，记录此次决定、原选择和请求次数。复问只检查局部行为；整周拟真度须在独立连续运行中重新评估。

该阶段使用原模型复问 6 个场景，10 次请求均首答有效。3 个自由时段均选择不用手机，其中白天的 1 个与参考活动不符。受挫后的两次选择都是 3 小时后再看。本地实测编号为 `resident_choice_20261128_163129_9306a0_final`。后续已完成明确询问用机意愿的十人七天运行，再以个人习惯和 LLM 建议共同决定用机的新版测量 32 个独立时段。[七天连续运行与自由时段检验](../../../report/2026结项/仓库发布/2026-11-28/seven-day-and-habits.md)
