# V4 登录接入与求助配对实验实施计划

从 `f54bf09` 开始，在单人第 5 天 09:00 的同一登录机会中，检验显式提供的昨日成败经历是否影响何时办理、采用哪种策略以及是否发出模拟求助请求。沿用 V4 计数协议、Python、pytest 和现有智谱客户端。

## 固定设计

- S0 使用原登录提醒。S1 只改模型实际收到的可见说明，告知今天不查不影响权益、明天仍可以查。两个情境各做 5 对成败对照，再各做 1 对相同输入重复，共 24 个决策点。冻结提醒措辞、发送顺序、共同随机数、人物、历史和模型设置后才可在线运行。
- 所有比较均使用机会模式。当前心理保持 50、九项需求保持 0.3，保留并列时产生的 `tool_need` 标签。机会是当天的新登录；昨日经历的直接作用是本次研究对象。通过昨日成败更新心理再观察次日的机制，需要另设实验。
- 合法延期、放弃、日常用 App 或不用 App 时停止。模型选择办理后，运行生产任务评价、独立/求助/回避评分、融合和抽样。受控帮助者接收真正的模拟请求；帮助送达和任务成败留作未观测。
- 报告四组描述统计、场景内的配对差异和相同输入的波动。所有决策及已接入子样本分别报告求助数和分母，注明无效、缺失及使用规则回退的判断。五次比较只用于描述这个人物和场景。

## 实现与验收

- [x] `examples/digital_friction_mvp/hourly_factorial_design.py` 与 `probe_hourly_intention.py` 生成、校验实际提示和替代动作，保留旧探针入口。
- [x] `probe_hourly_strategy.py` 接入任务评价、策略抽样及模拟求助接收，记录原始评分、规则权重、融合权重、来源和实际动作。
- [x] `analysis_hourly_factorial.py` 按冻结清单核对 24 点、区分分母和技术失败，输出配对变化方向与幅度。
- [x] `run_hourly_strategy_factorial.py` 默认只生成可审查的离线材料。显式在线时保存源码、逐次请求、逐点决策和汇总，限制请求次数并保留已完成记录。
- [x] 用真实参考数据和合成数据分别做零联网预检，用本地传输替身覆盖正式入口，并运行数字摩擦回归测试。

## 离线验收记录

两种历史均通过了 24 点清单和 8 条替代行为的接入检查。真实参考历史的 S0 输入与归档 V3 请求逐字段核对了人物观察、固定需求和采样参数。正式模型调用数为 0。

使用真实客户端和内存 HTTP 替身走完全部 24 点。受控回复指定一个情境接受、另一个延期时，产生 24 次规划、12 次任务评价和 12 次策略判断；实际进入模拟求助接收端的记录与逐点决策完全对应。模拟最后一点评价时遇到限流，程序保存已接入事实，未形成低层策略并标记运行中断。越界的模型分数单独保留原值，格式修复和规则回退分别记录。

数字摩擦测试共 686 项通过，依赖报告 3 条弃用警告。本地离线材料位于 `agentsociety_data/runs/hourly_strategy_factorial/`，其中 `hourly_strategy_20261127_210528_ec6142` 使用真实参考数据，`hourly_strategy_20261127_210528_6ec589` 使用合成历史。正式命令见[项目说明](../../../README.md)。
